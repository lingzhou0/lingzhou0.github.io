# lingzhou0.github.io — website update guide

My personal academic site: **5 hand-written, fully self-contained HTML files** in the repo
root. No static-site generator, no build step, no shared templates/includes. Live at
**https://ling-zhou.com** (CNAME) and https://lingzhou0.github.io. Deploy = commit & push to
`main` (GitHub Pages serves the repo root). **The editing commands (`/event`, `/talk-done`,
`/paper`, `/course`) finish by committing & pushing on their own when the result is clean; if
anything needed a judgment call or is worth a look, show the diff and ask before pushing instead.
For ad-hoc edits outside those commands, don't commit or push unless I ask.**

**Never read or edit** anything under `Backup/`.

## Pages and what lives where

| File | Sections (top → bottom) |
|------|--------------------------|
| `index.html` | bio · Research Interests · Contact · **Upcoming Events** · **Past Events (Selected)** (by year) |
| `talks.html` | **Invited Talks** (by year) · **Contributed Talks and Posters** (by year) · Regular Group Seminars |
| `research.html` | **Publications and Preprints** (All/Journal/Conference/Preprint filter) · Event Organization · Reviewer · Awards |
| `teaching.html` | Courses grouped by institution (`<h2>`), newest term first |
| `about.html` | long-form bio |

**Shared chrome is copy-pasted into all 5 files** (there are no includes): the
`<div class="nav">`, the `<style>` theme block, and the "Last updated" footer. Change one →
change all 5. The "Last updated" date is auto-generated by JS from the file's modification
time — **never hard-code it.**

## Universal rules

- **Newest first, everywhere.** Within every list and every year group the newest item goes
  at the **top**; year `<h3>` headings run in descending order.
- **Match the file you're editing.** `index.html`, `teaching.html`, `about.html` indent tags
  with ~8 spaces; `talks.html` and `research.html` are flush-left. Don't reformat surrounding code.
- **I am `L. Zhou`** in author lists — plain text, never bolded.
- **Each page writes dates differently** (see recipes). The same talk often needs 2–3 edits
  in 2–3 formats.
- Leave the commented-out blocks in `index.html` and the hidden "cats" paragraph in
  `about.html` alone.
- After edits, show `git diff --stat` and name the files touched.

## Orders → actions

### "new event …" → add an upcoming event (index.html only)
Insert one `<li>` into the **Upcoming Events** `<ul>` in descending-date order. Date format
**`YYYY/M/D`** (ranges `YYYY/M/D-D` or `…-M/D`):
```html
            <li><strong>2026/9/12:</strong> <a href="URL">Event Name</a>, Institution</li>
```
URL optional (plain-text entries exist). Add `, City, ST` if I give a location.

### "delivered / gave …" → move event to Past **and** add the talk (index.html + talks.html)
Two synchronized edits:
1. **index.html** — cut the matching `<li>` from **Upcoming Events**, paste it under the right
   `<h3>YEAR</h3>` in **Past Events (Selected)**, at the top of that year (create the year
   heading if missing). Keep the `YYYY/M/D` format.
2. **talks.html** — add the talk under **Invited Talks** (invited seminar / colloquium /
   conference talk — the default) or **Contributed Talks and Posters** (poster / contributed),
   under the right `<h3>YEAR</h3>`, at the top. Date format **`(Mon D, YYYY)`**:
```html
<li>
<strong>Talk Title.</strong>
Venue/Seminar, Institution (Sep 12, 2026).
<a href="URL">Link</a>
</li>
```
Write the **talk title in Title Case** — capitalize every major word; lowercase only articles,
conjunctions, and short prepositions (`and`, `with`, `of`, `in`, `the`, …). Use Title Case even
when the underlying paper/source title is sentence case (e.g. paper "Topological optimization
with birth and death cochains" → talk "Topological Optimization with Birth and Death Cochains").

If I gave the **same title** at multiple venues, use one entry with a nested `<ul>` of
per-venue `<li>`s (existing examples in the file). Drop the `<a>` if there's no link. Ask which
section only if genuinely ambiguous.

### "new paper …" → research.html  (give an arXiv id / DOI / URL if you have one)
Insert at the **top of the `<ol>`**, under the right `<h3>YEAR</h3>` (year = posting /
publication year; add the heading if it's a new top year). Every entry **must** carry
`class="publication-item"` and `data-category` ∈ `preprint` | `journal` | `conference` (the
filter buttons rely on it).
```html
<li class="publication-item" data-category="preprint">
<strong>Title.</strong><br>
Author A, Author B & L. Zhou.<br>
<em>Preprint.</em>
<a href="https://arxiv.org/abs/2603.25575">arXiv:2603.25575</a>
</li>
```
- **Journal:** replace the `<em>` line with `<em>Journal Name</em>, YEAR.<br>`, link label
  `Journal`; append ` |` + `<a>arXiv</a>` if there's a preprint.
- **Conference:** `<em>Venue YEAR.</em><br>`, link label `Conference` (+ optional `| arXiv`).

If I give an arXiv id, fetch title/authors/date and fill it in (keep me as `L. Zhou`); confirm
the author list before saving. Cross-check the canonical title against the active-papers table
in `/Users/lingzhou/0RESEARCH/AGENTS.md`.

### "new course …" → teaching.html
Insert at the **top** of the right institution's block (under its `<h2>`), newest term first:
```html
        <div class="course-item">
            <p class="semester-label">Fall 2026, <strong>Course Title</strong>, <a href="URL">Syllabus</a> · <span class="course-code">CODE, Sections …</span></p>
        </div>
```
Term = `Season YYYY` (`Spring`/`Fall`/`Summer`/`May`). Add a role (`Teaching Assistant,` /
`Mentor,`) before the title if applicable. Link label: `Syllabus`, `Course Page`, or
`Recitation Notes`. Drop the `<a>` and/or `<span>` if not provided. New institution → new
`<h2>` + its items. (When I move to OU in Aug 2026, add a `University of Oklahoma` `<h2>` at the top.)

## Out-of-the-box helpers (just ask, or use the slash commands in `.Codex/commands/`)

- **`/site-doctor`** — pre-publish check: Upcoming events whose date has passed (offer to roll
  to Past), publications missing `class`/`data-category`, nav drift across the 5 files,
  year-order sanity, optional dead-link scan.
- **Auto-roll past events** — find Upcoming `<li>`s dated before today and move them to the
  right year under Past, automatically.
- **arXiv import** — `/paper 2603.25575` builds the entry from arXiv metadata.
- **Propagate chrome** — "add a … link to the nav" or "change the accent color" applies the
  edit to all 5 files at once (since chrome is duplicated).
